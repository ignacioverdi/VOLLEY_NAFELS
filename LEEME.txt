EL HEATMAP DE DEFENSA — LA CAUSA REAL
=====================================

Un archivo: hm_defensa.html. Publicar y Ctrl+Shift+R.


LO QUE ENCONTRE
---------------
Todo lo que veniamos arreglando estaba bien puesto —los botones, la espera de
los datos, el modo— pero NADA de eso corria. Y por fin entendi por que.

Dentro del javascript hay una linea que arma el SVG de la cancha:

    s+="<style>text{pointer-events:none}</style>";

Alguien pego 40 lineas de CSS ADENTRO de esa cadena de texto:

    s+="<style>text{pointer-events:none}
    /* === ENCABEZADO: QUE NO SE ENCIME === */
    .header, .topbar, .top-bar { flex-wrap: wrap; ... }
    ...
    </style>";

Los saltos de linea CORTAN la cadena. En javascript una cadena no puede
ocupar varias lineas, asi que el bloque ENTERO deja de compilar.

Resultado: el script de la pantalla nunca corria. Ni la lista de jugadores,
ni el mapa, ni el modo. Ni en partido ni en entrenamiento.

Por eso todo lo que agregabamos parecia no hacer nada: el codigo estaba ahi,
pero el navegador lo descartaba entero antes de leerlo.


LO QUE HICE
-----------
Saque el CSS de adentro de la cadena y lo puse en la hoja de estilos de la
pagina, que es su lugar. El CSS se conserva igual —arregla el encabezado
cuando el titulo es largo— solo que ahora esta donde corresponde.

La linea vuelve a ser una sola:

    s+="<style>text{pointer-events:none}</style>";

VERIFICADO: los 4 bloques de javascript compilan. Antes uno no.


LO QUE DEBERIA PASAR AHORA
--------------------------
Con el script corriendo, la pantalla arma la lista con los datos que ya
estan:

    354 defensas de entrenamiento · 13 jugadores · 8 sesiones

Y el boton ENTRENAMIENTO / PARTIDO funciona en las dos direcciones.

Revise las otras 5 pantallas de heatmap: este error de CSS dentro de una
cadena solo estaba en defensa.
